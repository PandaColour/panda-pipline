# 贷款系统开发流水线默认记忆

本文件是流水线给目标项目初始化的长期记忆。它描述贷款业务项目的默认开发纪律，不代表某个国家、端、渠道或产品的固定事实。每次任务必须以用户本次提供的目标国家、目标端、需求文档、接口文档、设计稿和代码仓库为准；如果目标国家或目标端缺失，先要求确认。

## 基本认知

- 这是贷款业务系统，不是普通电商或内容 App。
- 后端是业务事实和风控决策来源，并负责业务规则与状态机。
- 前端负责端侧体验、系统能力接入、协议执行和本地会话处理。
- 通信协议、加解密、Token、Header、字段映射和错误分类属于基础设施，必须统一处理。
- 国家、渠道、产品、合规、支付、KYC、风控和运营配置都可能变化，不得写死在业务代码深处。

## 每次任务先确认

开始分析或实现前，先输出并核对这些内容：

1. 本次目标端、国家和业务范围。
2. 前后端职责划分。
3. 通信协议影响。
4. 加解密影响。
5. 数据模型和状态来源。
6. 依赖关系。
7. 非范围。
8. 待确认项。
9. 验收方式。

## 前后端边界

后端负责业务规则和状态机，包括贷款产品、额度、期限、费率、订单、账单、还款、展期、KYC 配置及校验结果、风控、授信、审核账号、黑白名单、自动跳转策略、OTP、登录注册、Token 签发、SSO、注销结果、支付渠道、支付 URL、H5 链接、客服/IM 数据、FAQ、评价状态、国家/渠道/产品配置，以及 API 字段、混淆映射、加解密开关、密钥和响应加密策略。

前端负责 UI 展示、交互、导航、表单输入、本地基础校验、系统权限、启动披露、强更、网络错误、Toast、Loading、SSO 弹窗、Token 本地存储和过期判断、登出或踢下线后的本地清场、公共 Header 注入、逻辑 API 到真实 path/字段的映射、请求加密、响应解密、明文旁路、错误分类、设备信息采集、Push、归因 SDK、行为打点、WebView 打开后端返回的协议/支付/投诉/客服 URL，以及 Debug Mock、联调日志和验收证据。

前端不得臆造后端业务结果：不本地推导额度、订单状态、审核账号或风控结果；不把倒计时结束变成自动借款或自动提交；不把“只有一个产品”当自动跳转依据；不把 HTTP 200 加密文字符串当业务成功；不把 401 当业务成功；不把 Mock 成功当真实联调成功。

## 通信协议

通信协议是独立基础设施，不归属于某个页面。实现前必须确认并沉淀 Base URL、Host、国家、渠道、产品标识、公共 Header、Token 注入和清除规则、API 信封结构、业务错误、HTTP 错误、网络错误、加密错误、解密错误、字段映射、path 映射、混淆表更新策略、加密接口范围、明文旁路接口、upload/download/multipart/H5 URL 特殊处理，以及日志可观测字段。

日志禁止打印密钥、完整明文和 PII。

## 加解密

加解密必须集中在网络层。业务模块只组装逻辑字段并消费明文模型；不得让每个业务 API 单独实现加解密。请求加密失败时不上送；响应解密失败时返回明确 crypto 错误；明文响应必须旁路，不要强行解密。Debug 样例向量只证明算法正确，不证明真实后端联通。缺少真密钥、VPN、白名单或后端配置时，标记为外部阻塞，不得伪造成功。

## Network Demo 抽象

`Network/` demo 是 App 端网络协议与加解密基础设施参考，不是要求 iOS、Android 或 H5 原样照抄 Swift 代码。实现时应抽象成所在端既有架构中的网络层能力：逻辑 API 到真实 path/method/字段的映射、Base URL 和公共 Header 注入、Token 注入与续期钩子、JSON body 统一序列化后加密、HTTP 状态处理、响应密文识别与解密、明文响应必须旁路、业务信封解析、错误分类和 Debug 可观测日志。

请求路径按类型区分：普通 JSON 请求才进入请求加密；请求加密失败时不上送；GET query、multipart upload、download、H5 URL 和无 body 请求必须有明确旁路策略。响应处理先区分网络错误、HTTP 非 2xx、空响应，再处理密文识别、解密和明文透传；HTTP 200 只代表传输成功，业务是否成功必须继续解析后端信封 code/data/msg 或接口文档指定结构。

字段混淆和 path 映射要集中维护，业务模型使用逻辑字段名；远程混淆表下载失败时可以回退内置表，但必须记录 fallback，不能把映射下载失败伪装成业务成功。强更、配置、协议、字典、上传等公共 API 应通过同一网络基础设施接入，不在页面内散落解析、解密或 mock 分支。

Debug Mock 只能作为显式、可观测、可关闭的联调辅助。样例 AES key、样例向量和自动 crypto mock 只证明端侧算法或页面降级可运行；配置真密钥、启用真实加解密开关或 Release 构建时必须关闭自动降级。日志可记录 api、错误分类、字节数、keyKind 等诊断字段，但不得打印密钥、完整明文、完整密文或 PII。

## 多国家和多端

国家和端差异优先沉淀为 country config、channel config、product config、feature flag、localized copy、currency/date/phone/id format、payment provider adapter、KYC document adapter、compliance branch 和 API host/profile。

iOS 需求遵循 iOS 工程既有架构；Android 需求遵循 Android 工程既有架构；后端需求保持 API 契约兼容并明确前端影响；H5、SDK 接入、接口协议、运营配置和合规分支按用户本次指定范围处理。未指定平台时，先确认目标端和目标国家。

## 实施顺序

按依赖拆分工作，不只按页面拆。优先完成基础协议层、会话和全局 UX，再做业务流程；归因、Push、审核账号、加解密、Mock 策略等横切能力单独收口。

## 验收纪律

报告必须区分编译通过、真实接口联调通过、Debug Mock 通过、静态验证和环境阻塞跳过。Release 不允许 Mock 后门。Debug Mock 必须显式、可观测、可关闭。业务 Mock 不能作为真实后端成功。样例加解密不能作为真实密文联调成功。

需求文档、接口文档和 Figma 冲突时，先标记冲突并要求确认。业务规则以后端接口和需求文档为准，Figma 主要作为视觉和交互参考。
