# Swagger 契约利用

Swagger/OpenAPI 的用途包括业务语义、实际协议和代码注释，不能只提取字段名。仅处理当前需求使用的接口与直接依赖；不限定语言、平台或框架，不改变角色权限、AC、调度和 FINAL_ANSWER 协议。

## 按角色读取

| 当前模式 | 必须读取 | 本阶段结果 |
|---|---|---|
| `breakdown` / `breakdown-review` | [来源与分析](references/analysis.md) 的拆分部分 | 可解析的契约入口、版本、接口归属及公共协议责任；不提前展开所有 DTO |
| `analysis` / `requirements-review` | [来源与分析](references/analysis.md) | 当前项契约表、缺口与验证口径；审核只读核验 |
| `development` | [实现与委派](references/development.md) | 真实契约对应的实现、字段注释、定向测试及开发报告 |
| `code-review` | [验收与复审](references/review.md) | 独立契约检查结论、稳定 issue 与有效证据 |

记忆整理、总结和回执补正仅处理已有事实，不借本 skill 重新获取契约、修改代码或执行验收。

## 来源与事实边界

按顺序查找：① 用户指定/需求物料中的 Swagger/OpenAPI、接口说明附件及其可追溯导出；② 仓库 `docs/`、`memory/interfaces.md` 中的接口文档；③ 当前任务的共享上下文、分析/需求文档契约表。使用第一个适用当前接口且版本可核实的来源；部分缺失继续查后续来源补齐，不以版本不符的旧文档覆盖新契约。记录 URL 或可解析文件路径、版本/哈希、具体 operation/schema 定位；不复制凭证。

- 在线读取失败时，继续使用有效本地导出与已交接契约表。文档来源可用和真实服务可连通分别记录；服务不可用不代表字段语义缺失。
- Swagger UI 的 `doc.html` 可打开不等于已读到 schema；定位其 OpenAPI JSON/YAML 或已有导出，沿 `$ref` 读取本项使用的参数、请求、响应和嵌套类型。无法读取则记录实际缺口。
- Mock fixture、已有实现、字段英文名及页面文案不自动成为生产协议。Mock 与权威文档不一致时，以权威契约为实现依据；在授权范围内修正替身或隔离并说明测试适配，不能为了让 Mock 测试通过而改变生产字段、Header 或认证格式。
- 文档存在歧义/冲突时列出双方来源、受影响字段和可确定部分，不擅自补枚举、单位、默认值、可选性或生产规则；代码中的容错默认值另标为实现策略。

## 按事实记录缺口，不使用通用 TODO 模板

| 事实 | 处理 |
|---|---|
| 真实服务/账号/环境不可用，采用 Mock | 在已有报告写原因、替身位置/范围、已验证结果、真实未验证项和补验条件；已有契约和字段注释照常落实，不因使用 Mock 向代码添加 TODO |
| 按来源顺序查找后，具体接口/字段确无可用语义 | 在已有报告列出缺失接口/字段、查过的来源、当前临时处理、影响及所需补充信息；代码仅在受影响位置写同样具体的 TODO 或引用这条缺口，不批量复制到其他类/路径 |
| 已有 description，但代码实现或注释遗漏 | 属于开发可修复的遗漏，当轮补齐；不能转成人类待办或用 TODO 代替 |

不要求固定 TODO 文案，也不以是否包含某句原文作为验收条件。具体待办应能回答“缺什么、影响什么、当前如何处理、补什么后能闭合”，例如：`TODO：缺少结清次数字段定义，当前保留接口返回顺序；确认字段名及计数口径后补接排序。` 仅在确有该缺口时使用，不把示例写成项目事实。

不因历史 TODO 的存在就认定整个接口无文档；当前范围内若已有可靠来源，开发补齐可修复遗漏并更新失效待办，不开展无关全仓 TODO 清理。
