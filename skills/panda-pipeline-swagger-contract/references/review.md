# 契约验收与增量复审

## 首审

对当前项涉及的接口与直接复用的公共协议，独立读取权威来源、分析表、开发报告和实际代码，完成下列检查。开发报告中的声明不作为通过证据。

| 检查项 | 必查内容 | 结论证据 |
|---|---|---|
| 来源 | 适用版本、operation/schema、文档与 Mock 的区别、具体缺口 | 来源路径/版本及定位 |
| 请求协议 | Method/path、Header 名称与必需性、认证位置/格式、Content-Type、multipart part | 实际请求构造及定向断言 |
| DTO/Schema | 请求及本项使用的响应字段、嵌套类型、序列化名、类型/可空/枚举/单位 | 源 schema 与源码对应 |
| 业务注释 | 所有本项已实现的接口字段有可追溯语义；类/路径有业务用途与接口映射 | 逐 DTO 的字段核对结论与代码位置 |
| 实际接入 | 原 AC 的数据来源、公共能力复用、最终请求、结果消费 | 调用链及有效测试 |
| 缺口边界 | 真正缺文档、Mock 差异、真实未联调分别披露；待办具体，已有描述未转交人类 | 具体受影响范围、已验/未验事实及补验条件 |

将检查结论写入既有 `code_review.md`，定向测试证据写入既有 `test_report.md`。每项记通过/不通过/未验证/不适用及依据；可按 DTO 或公共协议分组，不要求每个字段生成报告行，但不得只抽一个字段就宣称整个 DTO 通过。不涉接口的需求注明不适用即可。

## 阻断边界

以下阻断标准用于首审、既有 issue 及修复直接引入的回归；增量复审的范围外历史漏检按下节记录，不借此扩大返工范围。

- 已有可用 Swagger 语义却未落字段注释、仅有英文属性名/混淆映射/通用 TODO，属于已有契约实现门禁缺失，**不得通过**。源文档未知的限定不得要求开发猜测补齐。
- 已明确的 Header、认证格式、请求体/文件字段等与实现不一致，给出来源、代码位置、失败断言及可执行修复；Mock 成功、UI 截图、构建通过不豁免协议偏差。
- 缺语义来源且已按来源顺序查证并准确披露，不得仅因没有 Swagger 否决；按角色的既定降级规则审查可控实现和真实未验证范围。不能将“服务连不上”误判为“字段说明不可得”。
- 不要求开发补写固定 TODO 文案；契约完整但仅缺真实联调时，检查环境原因、替身验证和补验条件即可。真实契约缺口需具体待办，不能用一句泛化“请人类补接口”替代必要事实。
- 不把当前项未使用的全部 Swagger 接口、无关字段、重构偏好或真实环境不可控条件扩成新 AC。注释与契约检查是当前接口实现的既有质量门禁，不要求另造业务 AC。

## 增量复审

首审一次性列出当前范围可发现的契约/注释问题，分配稳定 issue ID，给出具体字段、来源、修复要求与证据。后续按角色规定只核既有问题、修复直接影响和直接回归；复用未失效的来源与检查结论，不反复联网、全量扫 Swagger 或重跑全部测试。

保留首审契约检查表，更新本轮受影响行。有效历史结论可引用其轮次和证据；首审未记录检查不能写成“已通过”。历史记录不全时先定点恢复已有源码/来源和报告证据，不默认重新执行全量审查。

首审漏检且与既有 issue、修复直接影响无关的历史缺项，记录为非阻断历史缺口：证据不足标“未验证”，已查实遗漏标“不通过”，写明来源、具体字段及影响，不伪装成新回归。本轮状态按既有问题与直接回归裁决；批准增量修复不代表该历史缺口已解决，报告必须保留事实，不得宣称全部契约门禁通过。此规则只限定复审处理，不豁免开发及首审履行完整门禁。
