# 实现、委派与自检

## 实现契约

1. 定位本项接口契约表和权威来源，再检查实际复用的 API 客户端、拦截器、DTO/Schema 和序列化映射。已有代码或 Mock 返回与文档不同，不视为文档失效；在当前调用链修复可确定的偏差。
2. JSON 报文使用项目既有的类型/Schema 和编解码机制，不新增无类型手拼报文。非 JSON 协议遵循实际编码工具；不为用此 skill 引入新框架。
3. 类/结构体顶部标明业务用途、HTTP Method 和实际 path；共享 DTO 引用其 schema 与使用接口的集中映射。混淆路径常量/API 定义标明业务别名与来源。
4. **每个已实现的接口字段都要有来源可追溯的业务注释。** 拷贝 Swagger description 或等价业务说明，保留文档给出的单位、枚举、可选性等限定；英文属性名、`SerialName`、类顶部 TODO 不算字段注释。类型与必填/可空规则可由类型/Schema 表达，但不能丢失文档语义或把实现默认值写成后端保证。
5. 文档与分析表已有说明时直接落实；表中遗漏的字段定点读取源 schema，不要求人类重抄。仅真实缺口适用 SKILL.md 的缺失披露规则。

例如文档说明 `countDownTime` 为“倒计时时间（单位秒），小于等于 0 返回 0”，代码注释必须保留这些语义；只写“倒计时”或 `TODO：补接口` 不足。源类型为 int64 时也要核对实现类型，不能只补注释而保留错误映射。

## 子任务委派必带信息

仅当需要委派接口相关工作时，在子任务消息中同时给出：

- 本 skill 的可读取绝对路径，要求先读 `SKILL.md` 和本规范；不能只传名字或假定子 Agent 继承父角色规则。
- 当前契约来源路径/版本与相关 operation/schema、分析表定位、当前实现/复用入口及工作范围。
- 交付要求：DTO/字段注释、真实序列化映射、相关请求断言、源码位置及缺口；明确 Mock 不是生产契约来源。

父 Agent 汇总前按原契约复核子任务产物。子 Agent 的“完成”、字段映射清单或测试全绿不能代替字段注释和最终请求检查；未落实的已知说明由开发补齐。

## 定向验证与报告

对本次使用/修改的协议选择最小充分测试，断言序列化后的实际请求与响应解析，而非只检查常量已定义：HTTP Method/path、必需 Header 名及认证格式、query/body、multipart part/Content-Type、嵌套 DTO 与当前 AC 涉及的单位/枚举。multipart 由客户端正确生成 boundary；不得把 JSON 全局 Content-Type 强加到文件上传。

断言预期值来自文档；与实现共用同一个可能写错的常量、或宽松 Mock 返回成功，不能独立证明符合契约。复用未失效的已有测试，不机械为每个字段重复建测试；替身验证与真实联调结论分开。

在既有 `develop_report.md`「后端接口与 mock 说明」中保留下表，可按共享协议/DTO 分组，不另建报告：

| 接口/公共协议/DTO | 契约来源及版本定位 | 实现与字段注释位置 | 与契约一致性 | 测试命令、断言与结果 | 具体缺口/真实未验证范围 |
|---|---|---|---|---|---|
| 当前范围 | 文件/URL + operation/schema | 文件:符号/行号 | 一致/不一致/未知，说明差异 | 新增或复用证据 | 无则明确无 |

报告写“一致”前必须实际核对源码；使用 Mock 时仍保留准确字段注释，在报告写后端不可用原因、替身范围、已验结果、真实未验证范围及补验条件，不要求固定 TODO 文案。仅真实契约缺口按 SKILL.md 写具体待办；已有文档支持的实现/注释遗漏由开发当轮补齐。返工更新受影响行，保留有效来源和证据。
