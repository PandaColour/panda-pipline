# 物料转换、索引与审计

当前目标和目录以任务输入为准。Figma 专用的 node-id、FRAME、inventory、原始响应与脚本审计仅适用于 Figma 来源；其他设计源记录实际页面/状态、来源定位、原件与转换证据，不虚构 Figma 字段。以下 requirements/R-xxx 是现有流水线布局，调用指定的真实路径优先，不能为匹配示例创建平行目录。

- **统一入口与职责：** 拆分/分析阶段保留设计原件并交接转换规范；Developer 负责当前平台的转换、工程入包和运行验证。后续补充资源必须复用同一已验证导出/转换入口与参数约定；入口缺失时由 Developer 在需求范围内建立最小可复用入口并记录命令/工具版本，不让各阶段另起一套临时转换。需求 Reviewer 只核对原件、元数据和验证安排；Code Reviewer 可按既有权限补充原始物料，需要生成/替换工程资源时交回 Developer。
- **原件与倍率：** 在 schema_version: 3 资产记录中保留来源节点/版本、原件路径/哈希、`design_width`、`design_height`、设计坐标单位和实际导出 `scale`；记录导出画布、viewBox/裁剪区域及效果外扩。位图明确设计尺寸、画布尺寸与实际像素的关系，允许有依据的小数倍率与取整，不能先取整设计值再乘倍率。矢量的像素尺寸标 N/A 并保留逻辑尺寸/viewBox；未知值写明缺口，禁止按文件名或默认 @2x 猜倍率。
- **转换与入包追踪：** 在当前物料映射表或既有补充映射中记录原件 → 转换工具/版本/完整参数 → 输出文件/哈希/像素尺寸 → 目标平台资源名、目录/资源集、逻辑显示尺寸及目标单位（如 dp/pt/CSS px）、密度/倍率声明 → 消费组件/状态。直接复制也记录复制与哈希一致性；同名不同来源/状态不得覆盖，去重须核实内容、样式和用途。原件保留，不能用加工后的低分辨率位图替代原件。
- **最终文件校验：** 按原件语义核对实际消费用途，不能把状态角标、遮罩、取景框或整页参考图当作业务插图/示例照片；不能只凭 asset 文件名选图。Developer 对转换后且实际入包的文件完成完整解码、尺寸/倍率/配置匹配、alpha/背景策略、有效图形边界与位置、异常留白、裁剪/阴影/渐变保真检查，并提供目标页面证据。留白、透明度和效果须对照设计，照片/设计白底不强制透明，设计留白不能机械裁掉。禁止使用系统预览缩略图或截图抠图作为正式资源；出现“大画布、图形缩在角落”等错误时从原始 SVG/Figma 节点重新导出/转换，不靠移动目录或放大错误 PNG 修复。
- **审计与复审：** 现有审计通过只证明其实际检查的内容。若脚本因字段缺失跳过尺寸检查，或未覆盖透明画布、平台入包文件，Developer 必须用可复现命令补验并记录结果；Reviewer 不得把未检查写成通过。需求阶段不提前要求尚未生成的平台产物；开发阶段可补齐的元数据/转换/验证遗漏返回 changes_requested。复审仅重查变更资源、直接消费页面及失效证据，未受影响且有效的原件/产物证据继续复用。

### 物料入口与独立索引

本批物料根入口固定在 `requirements/shared_context.md` 的「物料入口」。建立、修改或审核这一共享入口格式时，必须读取项目已安装的 `panda-pipeline-architecture/SKILL.md` 及其 `references/shared-context.md` 的物料入口规范，按当前角色权限执行；不因此加载全套架构规划。消费原件时沿已有共享入口定位当前 manifest，不新建平行根目录。

沿用现有小需求目录；已有原件在本项目录内其他位置时可按真实路径登记。原始资料来自共享缓存或其他目录时，核实来源与版本后复制所需原件到本项，保留原件，不用 ../ 跨项引用。manifest 内所有文件路径相对所属小需求目录，不能依赖当前 Shell 工作目录或归档前绝对路径。

`schema_version: 3` 的 manifest 是物料映射表的唯一维护入口：`frames[]` 标明页面/状态/node_id，`reference_screen.path` 指向参考图，`assets[]` 用 node_id、local_path、kind、format、usage、required、selection_evidence 与导出/复用参数标明原件及消费用途。需求正文、分析报告和开发报告引用 manifest 与对应节点，只补设计解释、接入动作及验证结果，不复制一份需同步维护的物料清单。精简正文不能删除索引、原件或来源路径。

每个 FRAME 的 `frames[].design_source` 必须登记 `path`、`node_id`、`revision`、`sha256`：原始节点/工具响应以 JSON 保存，推荐 `figma_assets/design_sources/`；文本型工具结果保存原始响应的 JSON 包装，不能只保存手写 Token 摘要或空对象。path 指向本项可读原件，node_id 对应当前 FRAME，revision 保留实际来源版本；来源未提供版本时如实记 unknown，并保留获取时间和内容哈希，不编造版本。共享父节点响应可被多个 FRAME 引用，角色须核对内容确实覆盖各节点；路径与哈希检查不等于设计语义已验证。`remote_read` 记录真实工具及 success/failed，失败须有 reason；REST 或历史调用不能冒充本轮 MCP 成功。可控资料缺口仍须补齐，真实缺失记录缺口与影响，不能伪造原始响应凑审计通过。

读取顺序：共享入口 → 当前 manifest → 当前页面/状态所指向的原始响应、参考图和素材 → 分析基准及代码。拆分建立入口并准备已知物料；分析在当前项补充精细资料与索引；开发沿用并增量补充；Reviewer 按已有只读/补充权限核对。分析和开发补物料无需修改原始需求正文；只读 Reviewer 不负责迁移。旧 schema_version: 1/2 仍按旧映射审计，报告 `legacy_requirements` 明确列出未检查原始设计源的项目，旧 passed 不等于新检查通过。未修改的旧包保留兼容；新建或补充物料时，由有写权限的生产角色将旧映射和本轮补充合并到 3，再检查来源与文件，不能只改版本号。原始数据确实不可得时保留缺口和审计失败，继续可控工作，不降回旧版取得 passed；升级版本不代表物料已完整。
