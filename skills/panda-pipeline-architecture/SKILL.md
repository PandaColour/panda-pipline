# 项目架构与共享上下文

本 skill 集中维护共享文档格式与架构规划模板。项目类型、技术栈和业务规则来自当前需求与仓库事实；不扩大角色权限、不新增 AC、不更改调度或 FINAL_ANSWER 协议。使用调用消息提供的项目已安装 skills 目录，不依赖自动发现。

## 按模式读取

涉及共享上下文或架构约束时，读取 [共享上下文格式](references/shared-context.md)，按当前模式处理：

| 模式 | 读取与执行范围 |
|---|---|
| `breakdown` | 建立本批共享文档；初始化项目再读取 [架构规划模板](references/planning.md)，既有项目仅补实际架构与本次影响 |
| `breakdown-review` | 只读核对共享文档、能力归属与规划完整性；涉及初始化架构时读取 [架构规划模板](references/planning.md)，不要求提前实现或运行 |
| `analysis` / `requirements-review` | 读取当前项直接相关约束与能力入口，细化/审核接入方案；不因读取模板要求重新规划全项目。Break 分析与需求审核只读共享文档；简化分析仅可维护角色已授权的物料入口及当前项 inventory |
| `development` | 消费当前架构与依赖；仅在角色授权时更新本轮相关条目及实现证据，不修改架构核心约束或自行标记 verified |
| `code-review` | 独立核验实际接入；仅在角色授权时更新已核验的相关条目状态/证据，不代写实现或修改归属 |
| `summary` | 只读核对既有事实、未决事项与证据；不补全模板、不修改共享表、不重新规划或验收 |

需要解释现有架构约束时可定点读取规划模板相关部分；不全文重复架构声明。权限以当前角色 prompt 和调用任务为准，表格模板不是写入授权。简化流程不因加载此 skill 获得 Break 的共享能力表写权限；无关任务和回执补正不补共享文档。

共享文档是本批次临时公共信息，随本轮 requirements 归档；不写入 memory、不从归档清单恢复待办。更新只涉及当前任务的相关条目，保留未受影响的字段、来源与证据；有等价且可追溯内容时沿用既有格式，不要求下游全量重排。首审/复审仍遵循角色既有边界，不能以格式迁移为由扩大检查或把计划当已实现。
