## UI 资源缺口与验收结论

仅对原始需求涉及 UI 的部分执行。按 AC、页面/状态、资源或属性记录缺口：来源节点/版本、MCP 实际发现及调用结果、本地查证路径、缺少内容、可继续还原部分、临时处理、未完成/未验证范围和补验条件。记录复用资料的原始时间与本次核对范围；历史 remote_reads、审计 passed 或别的角色成功记录不代表本轮成功调用 MCP。没有图片查看工具时如实记为未完成视觉核对，不用 XML/文件检查冒充看图。

- **有依据可实现：** 本地已经明确的布局、尺寸、字体、颜色、裁剪、资源用途和状态必须落地；默认组件方便、资源放入正确目录或功能可运行，都不能豁免业务控件结构与设计的差异。需求明确覆盖设计、系统所有区域或动态内容差异须说明依据，不能把业务区域差异统称平台差异。
- **素材内容与用途：** 在本角色准备、选用或审查素材时，实际打开对应图片并核对“图中内容 → 来源节点 → 目标组件/状态”；文件存在、尺寸正确、审计 passed 不证明用途正确。取景框不能充当证件示例，相机按钮不能表示模糊照片，错误角标不能表示曝光示例；这类语义错配不是低清或“本地缩略近似”。优先复用本地已有对应原件；确实缺失则按缺口规则交接，不拿无关素材填充后宣称通过。拆分/分析只核对原件用途与后续验收安排，不提前要求工程入包或运行截图。
- **仅部分资料缺失：** 缺高倍率图片时，可暂用经核实的低倍率原件，继续核对显示尺寸、比例、位置和布局；清晰度不达标记未通过，无法判断记未验证。缺字体或某张图片不意味着其他已知样式也可简化。无法从已有原件可靠补足的外部缺口，不要求重复撞限流或等待服务恢复。
- **关键资源确实不可获取：** 保持原 AC，完成有依据的功能和视觉部分；必要的临时展示须在报告标明替代范围、原设计缺失及替换入口，不得以相近图标、错误素材或静态图冒充目标资产/动效，不得截图抠图伪造原件。可由本地原件转换、代码或现有工具解决的缺口不归类为外部缺失。
- **分开结论：** 按 AC 编号和 `逻辑`/`UI` 类型分别记录证据、结果及资源/环境限制；逻辑通过不能代替 UI 通过，截图也不能证明请求/状态流转正确。同一有效证据可供相关 AC 引用，结论仍逐条给出。下游接收未调整的历史混合 AC 时保留原编号，在该编号下分记逻辑与视觉结果，任一未通过/未验证不能整行标全部通过。允许按既定降级继续交付可控部分，approved/completed 不代表原始 AC 全部通过；不新增最终回执 status。

本节限定全文“缺一不可”“物料齐全”和“全部通过”等表述：可控遗漏须修复；真实外部缺口如实交接，验收其余可控部分。拆分/分析只验证资料、范围与后续验收安排，不提前要求尚未实现的界面截图或工程资源。关键需求来源不可访问致范围/契约无法确定时，仍按该阶段既有资源访问协议处理；仅缺某张图、字体或高倍率版本不能自动等同于整份需求不可分析。
