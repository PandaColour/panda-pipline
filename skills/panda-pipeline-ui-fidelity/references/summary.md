# 总结既有 UI 证据（summary）

仅原始需求含 UI 时执行；只读已有报告、设计和运行证据，必要时查看已有图片核对矛盾，不重新获取 Figma、下载物料、不启动设备、不重新开发或开展全量验收。结果只写调用指定的总结报告，不修改上游报告、源码、共享状态或关闭交接项。

UI 目标核对原件、转换、工程引用与实际运行截图，按适用格式追溯倍率/画布元数据，不用原件审计通过代替最终资源合格。没有 UI 的目标不要求图片或设备证据。

- 核对视觉 issue 的关闭依据是否回到原始 AC，不能把“示例区已有”“图标已替换”直接计为视觉通过；素材内容与用途错配不是低清近似，不能因被标成非阻断建议而忽略。发现报告与图片相矛盾时，只在总结中保留具体差异和未通过事实，不修改上游报告或另开全量验收。

- 按页面/状态核对截图构建版本、关联改动及新增/仍适用/失效依据；复用未受影响旧证据须保留原版本。已声明失效却仍被引用通过的项，记录证据矛盾，未澄清前不计通过。对屏幕比例、系统安全区或服务端文案引起的合理适配差异，沿用 Developer/Reviewer 已核实且仍有效的“已接受差异”及依据，不重新计为未完成/未验证或要求匹配设计样例的绝对像素、行数；仅有差异理由却无验证依据不能据此计通过。此例外不豁免原需求明确要求、裁切/重叠/操作不可达及无关样式错误；Mock 文案不计为真实联调。

- 总结只读核对验收证据，不启动设备或重新开发。对视觉通过结论核实是否有实际打开设计/实现图片的可追溯对照记录及具体差异结论；只有并排图文件、XML、哈希或 approved 时，不能继承为视觉通过。记录缺少对照、已知差异与资源缺失的区别；检查可疑结论时可查看已有图片，明确本次核对与历史行为，不能把本次看图说成原审查已完成。
