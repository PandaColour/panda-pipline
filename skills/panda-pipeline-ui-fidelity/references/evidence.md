## UI 实现与视觉证据有效性

- **按字段落地：** Token → 代码映射必须覆盖当前 UI AC 实际适用的尺寸、内外间距、字体/行高/字重、渐变色标与方向、描边/阴影、裁剪和选中/未选中态。仅列全局主色和字体不证明整页还原；本地结构化数据中的确定值不得改为目测近似值。
- **按状态取证：** 每条视觉证据关联 AC、平台、页面/状态、设计节点/版本、构建标识、实际截图和触发步骤/数据。不同视觉状态不能共用同一实际截图冒充覆盖；只有相同可见断言且有状态等价依据时才可复用。Mock/fixture 应驱动实际业务组件进入目标状态；仅含测试说明/调试按钮的替代页面不能证明会话、评价等业务 UI 通过。
- **实际打开并对照：** Developer 提交前、Code Reviewer 验收本轮需核验的视觉项时，分别用可用图片查看工具打开实际截图与对应设计基准图，或信息清晰且来源可追溯的并排图。仅看运行截图不等于完成设计对照；生成/拼接图片、读取文件尺寸/哈希、UI XML 文案、测试通过或他人结论均不能代替查看。按页面/状态记录查看的设计/截图路径、构建/设计版本、所用查看工具或可追溯记录，以及核对的布局、尺寸、字体、颜色、图标/素材、裁剪、状态和差异；不能把本轮打开说成历史已看。相同状态的多条 AC 可引用同一份已核对记录，未受影响且有实际对照结论的历史证据可复用，无需逐 AC 重复打开。无法查看或对照条件不足时保留未验证，交接可补动作，不虚构视觉通过。
- **可比较且实际检查：** 先确认设计画板逻辑宽、参考图实际像素与导出倍率，以及运行截图像素、逻辑 viewport、density/fontScale、安全区和必要裁剪；仅凭图片宽高不能判定 UI 尺寸。并排展示先将对应业务画布等比缩放到统一展示宽度，分别标注设计/运行、原始 px、逻辑宽度、缩放系数和裁剪区域；例如逻辑宽均为 375 的设计图 375 px 与运行图 750 px，运行图缩放 0.5 后并排。宽高必须使用同一缩放系数，长图保持内容比例并分段或留白，不强拉到相同高度；不同逻辑 viewport 仍按既定响应式规则检查，展示同宽不代表布局应完全相同。保留原图，缩放图仅用于对照，不回写物料；图形边界和清晰度需回查原图，换算值不得从缩放后像素直接冒充实际 dp。逐项记录设计值、实现值、差异、容差依据和结论；生成并排图不等于完成对照；必须判断图中差异是否满足原始视觉 AC，不能只确认目标态存在。截图缺失、状态不符或已失效应保留未验证；已确认超差应保留不通过。没有阈值也不能放过渐变变纯色、图标状态错误等明确不符；P1 标签、配额不足和 runnable 均不构成容差依据。
- **逐页证据有效性：** 在既有证据表按页面/状态列明截图路径、实际构建版本、关联改动及“新增／仍适用／失效”的依据。新构建产生不自动使全部旧图失效；复用旧图须核实相关代码、资源、配置与设计基线未受影响，并保留原构建标识。已声明失效的图不得支持通过；如原失效声明有误，先明确更正具体条目及依据并同步引用，不能整批作废后又默默复用其中两页。共享改动只补验直接影响页面；缺证据记未验证，实际不符记不通过。
- **有依据的差异边界：** 按 [设计来源与验收边界](sources-and-boundaries.md) 中的可接受差异规则核实并记录可接受差异；默认组件、P2/建议标签不能替代依据。其余偏差仍按原始 AC 检查，素材误用不得降为普通建议，真实资源缺失沿缺口规则处理。
- **直接回归：** 修改共享主题、排版、颜色、组件或资源时，沿实际消费路径列出受影响页面/状态及证据失效范围，补验直接影响项。例如修改按钮文字默认色，要验证直接受影响的深浅底按钮；修改底栏状态，要同时验证图标与文字。未受影响且仍有效的证据可复用，不能扩张成无关全量重测。
