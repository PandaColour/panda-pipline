# UI 拆分与拆分审核

只处理本批明确交付的范围，逐步把原始资料交给当前项精细分析，不在拆分阶段展开全项目组件级精修。Figma node-id、FRAME、inventory 与 Figma 原件获取仅在当前设计源为 Figma 时适用；其他设计源交接实际来源定位、页面/状态、版本与资料路径，不虚构 Figma 元数据。下文 requirements/ 与 R-xxx 是 Break 默认布局，调用指定路径优先；无 R 编号时使用当前需求实际目录，不新建虚构项。

## 拆分交接（breakdown）

为当前交付范围建立 AC → 页面/状态 → 设计节点/基准 → 独立资源与用途的对应关系；同一素材的角标、遮罩、背景、示例照片等不能因文件名相近混为一项。公共上下文写明原件目录、来源登记/物料索引入口与版本、工程转换责任；已存在时沿用当前路径，不另建平行目录。逐项交接已确定的视觉属性与真实缺口，不将缺少高清原件扩大为整页可自由简化。视觉断言必须安排运行截图与设计对照；纯逻辑 AC 仍按其充分证据安排。拆分不提前宣称视觉已验收。

每个涉及 UI 的拆分项保留 `平台列表`、`状态列表`、页面/状态对应的设计定位（Figma 使用 `Figma node-id`）、设计资料路径与版本和已知 `容差策略`。viewport/safe area 与 `business_canvas`/`platform_owned`/`external_asset/content` 按已知依据交接，未知留给本项分析查证。验收摘要和执行索引引用本项设计入口，不重复逐组件属性。Figma 来源的全部 FRAME 范围与原件审计不得抽样遗漏；组件精确值由本项分析细化，工程转换及视觉结果由开发和代码审查验证。

涉及 Figma 时，以 `_figma_inventory.json` 核对当前范围内全部 FRAME 的页面/状态归属，不得抽样。按节点/版本去重读取原始结构与参考图，完整父响应已覆盖子节点时直接引用。下载或复用已确认必需独立原件并运行物料审计；筛选/下载/审计按 `panda-pipeline-ui-assets` 的拆分模式执行。审计 passed 不代表已完成精细分析或视觉验收。

物料入口固定在 `requirements/shared_context.md` 的「物料入口」，指向范围清单和各 `R-xxx-name/figma_assets/asset_manifest.json`；manifest 保留页面/状态/node-id、原始响应及版本/哈希、参考图、候选筛选依据和原件用途。需求正文和索引引用该入口，不复制完整映射表。已知可获取必需原件不得故意留给下游；未查清精细属性交接给当前项分析，局部外部缺口逐项说明影响及补验条件。

原始混合要求拆为独立编号的逻辑/UI AC，保留共同来源、页面/状态及优先级，不拆成脱节的两个需求。UI 按页面/组件状态合理归组，不为每个样式值新增 AC。安排后续设计/运行对照，不能把视觉验收降为单测或文件存在；没有数值容差时不编造阈值。

## 拆分审核（breakdown-review）

审查每个 UI 拆分项的 `平台列表`、`状态列表`、设计定位（Figma 使用 `Figma node-id`）、设计来源路径/版本及已知 `容差策略` 是否可追溯，viewport/safe area 和 `business_canvas`/`platform_owned`/`external_asset/content` 是否有依据或明确待本项分析核实。执行索引可引用对应文档，不要求复制组件明细。Figma 来源的全部 FRAME 范围与原件覆盖不得抽样遗漏；拆分通过不代表完成组件级精修。不以缺少全项目逐组件 Token 表、实现代码或运行截图退回拆分；必须拦截范围丢失、AC 错绑、已知约束弱化、可获取原件遗漏及无具体影响说明的缺口。

首审完整核对当前范围、原件与验证安排；只读运行审计并独立核实远程/本地依据，发现一个漏项需完成当前需求范围内同类检查，一次性列出问题集。物料全程只读，仅写审查/审计报告，可修复遗漏返回 changes_requested 给 Requirement Breaker。复审只查已有问题与直接影响项，不因加载本规范重新全量读取。

本地物料不完整时区分资料范围：仅关键来源缺失使范围/必要契约无法确定才按角色的资源访问阻塞协议处理；具体图片、字体或倍率不足按资源缺口规范继续可控工作，不能虚报物料审计通过。
