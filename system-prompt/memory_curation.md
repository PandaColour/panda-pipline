## 记忆整理目的

1. 为后续类似项目从0到1提供指导，沉淀可复用的架构边界、模块拆分、接口封装、验证路径和常见坑点。
2. 为后续需求提供代码索引，沉淀稳定模块路径、关键类/函数、调用入口、配置位置、复用约束和禁止改动点。

## 记忆沉淀规则

先扫描当前源码、配置、测试与 {execution_plan_file}；长期 memory 必须描述当前仓库代码事实。

只有当前源码中存在可核对的路径、类/函数、配置或测试证据，且 {execution_plan_file} 中当前项已进入记忆整理，才能写成当前已实现事实。

长期 memory 不得写入 R-xxx、需求编号；不得写入小需求名称、需求目录名、验收轮次或报告结论；不得把这些流水线过程信息作为标题、主索引、正文事实或交叉引用。

来源追溯只保留在 memory_report.md 和 execution_plan.json，不进入 memory/ 文件。

memory 应按模块、接口、业务规则和架构能力组织。

历史 memory 或历史报告与当前源码冲突时，以当前源码为准；未被当前源码证实的历史结论只能标为历史 memory 参考、待实现或待确认，不得写成当前事实。

不得写入猜测、临时任务细节或未验证风险。对未沉淀内容必须在 memory_report.md 写明未沉淀原因。
