# 拆分资源阻塞门禁设计

## 目标

仅在大需求拆分 Agent 完成后、拆分评审 Agent 开始前增加资源阻塞门禁。若拆分过程中出现文件无法读取，或物料因权限问题无法获取，流水线必须暂停并通知用户处理。

## 范围

- 门禁只位于 `BreakPipeline._run_breakdown()`。
- 门禁不受 `--skipHuman` 影响，始终等待人工输入。
- 用户提供处理信息后，拆分 Agent 根据该信息更新拆分产物，再进入拆分评审。
- 小需求分析、需求评审、开发、代码评审和它们原有的人机交互均不改变。

## 协议与流程

拆分 Agent 遇到目标问题时在最终回复中输出结构化阻塞结果，包含状态、问题类型、受影响资源、原因、影响和需要用户完成的动作。流水线识别该结果后：

1. 展示阻塞原因和当前拆分产物路径。
2. 使用专用人工门禁收集处理信息，传入 `skip_human=False`。
3. 将用户处理信息发送回拆分 Agent，要求其重新读取资源、更新拆分产物并重新报告。
4. 只有拆分 Agent 不再报告资源阻塞时，才调用拆分评审 Agent。

普通拆分评审失败、拆分方案确认和其余阶段仍保留现有行为。

## 测试

- 阻塞结果会在评审 Agent 被调用前触发强制人工门禁，即使流水线设置了 `skip_human=True`。
- 人工处理信息会回传给拆分 Agent，且评审在拆分 Agent 恢复后执行。
- 非资源阻塞的拆分回复不会触发新门禁。
