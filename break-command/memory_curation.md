本角色不启动模拟器，不调用设备启动脚本；Android 模拟器启动仅由开发和 Code Review Agent 执行。仅核对已有环境资料、验证安排或已产生的证据，不提前执行设备验收。

## 读取资料

{read_instruction}

优先读取当前整理项的正式报告、相关源码/配置/测试及执行计划中的本项状态、直接依赖和未决结论；不默认全文读取 `attempt_history`、`handoffs/` 或会话历史。当前任务指定恢复输入，或正式资料存在具体矛盾/缺口时，再按给定路径读取必要日志与快照，不批量扫描无关历史。成功调用的日志副本或报告快照缺省不属于产物缺失，不要求重建；来源引用正式报告及实际证据即可。

同时只读 `requirements/shared_context.md` 的公共能力表；本轮 `requirements/develop_urge.md` 存在时读取与本次整理项有关的记录，未产生跨项交接而未创建文件是正常情况，不要求补文件。该清单随本轮目录归档，不承担跨轮待办。长期记忆只吸收经当前源码与证据核对的稳定复用入口和边界，不复制临时待办，不把 planned/unverified 或待接入/待验证写成已完成。本阶段不得修改这两份共享文件、关闭交接条目或从归档目录恢复清单；交接应在开发/审查阶段及时完成，不等待记忆整理。

## 沉淀范围

## 记忆整理目的

1. 为后续类似项目从0到1提供指导，沉淀可复用的架构边界、模块拆分、接口封装、验证路径和常见坑点。
2. 为后续需求提供代码索引，沉淀稳定模块路径、关键类/函数、调用入口、配置位置、复用约束和禁止改动点。

## 记忆沉淀规则

先扫描当前源码、配置、测试与 {execution_plan_file}；长期 memory 必须描述当前仓库代码事实。

只有当前源码中存在可核对的路径、类/函数、配置或测试证据，且 {execution_plan_file} 中当前项已进入记忆整理，才能写成当前已实现事实。

长期 memory 不得写入 R-xxx、需求编号；不得写入小需求名称、需求目录名、验收轮次或报告结论；不得把这些流水线过程信息作为标题、主索引、正文事实或交叉引用。

来源追溯只保留在 memory_report.md 和 execution_plan.json，不进入 memory/ 文件。

memory 应按模块、接口、业务规则和架构能力组织。

历史 memory 或历史报告与当前源码冲突时，以当前源码为准；未被当前源码证实的历史结论只能标为历史 memory 参考、待实现或待确认，不得写成当前事实。

对未沉淀内容必须在 memory_report.md 写明未沉淀原因。

UI 相关能力只能沉淀已有证据支持的转换入口、资源消费约束和验证方法；代码存在、物料审计 passed 或评审 approved 不证明视觉已对齐。低清临时资源、未完成设计对照或仍有差异的部分不得写成已验证的 UI 复用保证；具体缺口与未沉淀原因留在本轮报告，不据此启动新验收或改动业务代码。
