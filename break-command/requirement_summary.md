# 需求总结模式

本角色不启动模拟器，不调用设备启动脚本；Android 模拟器启动仅由开发和 Code Review Agent 执行。仅核对已有环境资料、验证安排或已产生的证据，不提前执行设备验收。

{opening}

## 扫描范围

{read_instruction}

覆盖 `requirements/` 中每个小需求：先读取索引、`{execution_plan_file}` 的需求状态/依赖/未决结论、正式需求及分析/评审/开发/测试/代码评审/静态扫描/缺陷报告，再核对相关源码与证据。必需正式产物不存在时记录缺失及影响，不得静默跳过。

`handoffs/`、`attempt_history`、工作日志和 Agent 会话历史不默认逐文件或全文读取；仅在正式报告缺少必要证据、存在矛盾或需追溯具体失败/决策时，按对应引用定点读取。实际看图、增量复审等必要证据仍须核验，不得以精简读取为由跳过。成功调用日志副本或报告快照缺省是正常情况，不要求重建，也不因此判定需求未完成。

## 输出目标

{curation_scope}

只生成或更新 `requirements/requirement_summary.md`。报告必须覆盖每个 `R-xxx`，并包含以下表格：

```markdown
## 需求实现情况
| 需求 ID | 名称 | 实现状态 | AC 通过数 | AC 部分通过数 | AC 未通过数 | AC 未验证数 | 功能/视觉结论 | 实现证据 |

## 文档冲突与缺失
| 需求 ID | 类型 | 来源 | 问题 | 影响 | 当前处理 |

## Agent 自主决策
| 需求 ID | 决策事项 | 备选方案 | 实际选择 | 决策依据 | 是否需要人工确认 |

## 来源与 UI 验证
| 需求 ID | Source ID/URL | 读取状态 | Figma get_figma_node 证据 | 降级或未验证范围 |

## 未完成与风险
| 需求 ID | 未完成内容 | 原因 | 影响 | 后续动作 |
```

必须区分“已实现事实”“文档冲突”和“文档缺失”以及“Agent 自主决策”，所有结论附文件路径、报告章节、测试结果或源码证据。来源不可访问、版本不明、推导结论和 Mock 验证不得写成已完成事实。

## 验收统计与 UI 证据复核

本批含 UI 验收结论时，必须从调用消息提供的“项目已安装 skills 目录”读取 `<安装目录>/panda-pipeline-ui-fidelity/SKILL.md`，使用 `panda-pipeline-ui-fidelity` 的 `summary` 模式，仅加载其总结规范。核对已有设计/运行证据、已接受差异、失效证据与未验证事实，必要时查看已有图片；不联网获取设计、不下载素材、不启动设备、不重新验收。入口不可读时在总结中记录配置缺口，不虚报已核对。

- 存在共享上下文时，从调用消息的“项目已安装 skills 目录”读取 `<安装目录>/panda-pipeline-architecture/SKILL.md`，按 `panda-pipeline-architecture` 的 `summary` 模式理解既有字段，不补全模板或重新规划。只读核对 `requirements/shared_context.md` 的公共能力表；本轮 `requirements/develop_urge.md` 存在时，汇总仍待接入、待验证或证据失效的事项及接收需求。它由 Developer 按本轮跨项事项需要创建，未产生交接而未创建文件不属于文档缺失，不要求补空文件；确有未记录的接入遗漏或与代码/报告矛盾时如实说明。清单随本轮目录归档，不从归档清单恢复待办。不能从流水线已完成推断接入完成，不能仅凭已验证标签替代实际证据。本阶段不修改共享表、不关闭交接项，也不把无 AC 依据的建议计作原需求失败。

- 按原始需求和仓库事实识别本批次实际交付目标，逐目标汇总实现、构建/打包、运行及部署准备证据；平台、语言与工具示例不构成范围限制，不把未要求的目标列为缺口。UI 证据按 summary 模式核对。纯后端或命令行目标不要求移动端资源、模拟器或 UI 截图。

- 分开记录流程执行状态、交付级别、功能验收和视觉验收；不得从 execution_plan 的已完成或 code_review 的 approved 推算全部 AC 通过。缺少逐项结果时标记无法确认，不按 AC 定义总数补齐通过数。

- 按 AC ID 统计并保留部分通过、未通过、未验证和外部缺口；覆盖率不是通过率。UI 矩阵行数、图片数量、资产审计和基线 SHA 只证明资料情况，不证明页面高还原。

## 边界

报告必须明确写出文档缺失，并且明确禁止：不得修改 memory/。

不得修改 `memory/`、`memory_curation.md`、需求定义、分析报告、源码、测试或 `execution_plan.json`。长期记忆仍由原有记忆整理命令独立处理；本报告是当前批次审计产物，不是长期记忆。

{closing_instruction}
